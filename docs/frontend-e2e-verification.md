# MemberFlow — браузерная проверка frontend

Дата: 13 октября 2026. Настоящий Google Chrome через Playwright, development mode, уже работающий `http://localhost:3000`. Отдельный Next.js остановил попытку запуска из-за существующего процесса; сервер пользователя не перезапускался. Symfony и production API-режим не изменялись.

## Адаптивность

Проверены **390, 430, 768, 1024 и 1440px**: Customer Page Builder, публичная Customer Page, список/статистика клиентов, Overview, Settings, существующий Staff Scanner, модальные формы Loyalty и мобильная навигация. Для LV/RU дополнительно проверены Customers, модальная форма Loyalty, Builder и публичная страница на всех пяти размерах. Проверяется ширина документа, границы модальных окон и доступность кнопок; сохранены скриншоты.

Существующие homepage/Pricing-тесты также проверяют EN/LV/RU, навигацию, FAQ, адаптивность и axe-accessibility. График и таблица могут иметь собственную контролируемую прокрутку; она не растягивает страницу.

## Исправленные реальные дефекты

1. **Зависание при повторном выборе текущего бизнеса.** UI сбрасывал данные, но неизменившийся business ID не запускал загрузку. Повторный выбор теперь закрывает меню без сброса.
2. **Customers шире 390px.** Минимальная ширина SVG растягивала grid-контейнер. Ограничены grid tracks и минимальная ширина дочерних панелей; горизонтальная прокрутка остаётся внутри графика.
3. **Шапка RU обрезала «Создать».** Длинное название раздела конкурировало с действиями. Название корректно сокращается; действия сохраняют доступную ширину.
4. **Неточное объяснение локальных действий Scanner.** Подтверждение теперь использует общий текст локального прототипа вместо старого утверждения об отсутствии изменений баланса.
5. **Непонятная потерянная связь Campaign → Offer.** Недоступное предложение обозначено в выборе; ошибка предлагает выбрать существующее предложение или убрать связь. Переведено EN/LV/RU.
6. **Недостаточный контраст мелких подписей homepage.** Точечно затемнены номера и подпись прогресса; композиция и основная палитра сохранены.
7. **Язык документа Customer Page сбрасывался после reload.** RU/LV-интерфейс оставался переведённым, но `<html lang>` возвращался к EN. Customer Page теперь синхронизирует язык документа и обычную cookie предпочтения языка; E2E проверяет reload для обоих языков.

## Тестовая инфраструктура

- Добавлены **11 E2E-тестов** в `tests/dashboard.spec.ts`; существующие 7 тестов `tests/home.spec.ts` сохранены.
- Каждый тест получает отдельный BrowserContext. Данные создаются через UI, а не записываются в storage для обхода сценариев. Storage меняется напрямую только для специально проверяемых повреждений и отсутствующих ссылок.
- Проверяются необработанные browser errors и локальные HTTP 5xx. Для падений сохраняются screenshot и trace; автоматические retries не скрывают ошибки.
- `playwright.config.ts` поддерживает локальный Chrome, альтернативный путь `PLAYWRIGHT_CHROME_PATH`, `PLAYWRIGHT_BASE_URL` и повторное использование существующего development server. Если Chrome отсутствует, нужен установленный Playwright Chromium.
- Запуск: `npm run test:e2e`. HTML-отчёт: `playwright-report/index.html`; скриншоты и traces: `test-results/`.

## Границы проверки

Это frontend-прототип с локальными данными в текущей вкладке. Не проверены и требуют Symfony: реальная регистрация/авторизация/OTP, права и изоляция на сервере, авторитетные начисления/списания, Wallet issuance, публикация и доставка кампаний, социальный OAuth, оплата/подписки, production persistence, назначения новых абонементов. Реальные устройства, Safari/Firefox, физическое распознавание камерой и печать бумажного QR не входят в выполненный Chrome-прогон.

Никаких новых разделов, новых backend endpoints, фиктивных отправок или изменений тарифов не добавлено.
